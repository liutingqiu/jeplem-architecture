# JEPLM 辅助目标重定位：记忆内容预测在长延迟监督任务上的决定性帮助

> 日期：2026-08-10（夜间运行）
> 性质：JEPLM 辅助目标重定位的强正结果（与此前负结果链互补）
> 关联：JEPLM_ROUND1/2_REPORT.md（MemoryS7 负结果）、DECIDE_AFTER_DELAY_REPORT.md（§6 RL 诊断）、NIGHT_RUN_20260809.md

---

## 一、背景与动机

JEPLM 辅助目标此前全是负结果：
- MemoryS7 RL 上 SPR 式 latent 预测无增量（round 1/2）；
- DecideAfterDelay RL 上给 evidence 加 predictor 头掉 0.10（0.964→0.865）——aux 进 RL 策略梯度是**负担**；
- 真实 v2 语料（8 帧延迟）上 aux 可学但主任务饱和无增量。

**重定位假说**：aux 的价值是任务依赖的——在**监督 + 记忆保持压力**场景（长延迟回忆）下，"记忆内容预测"（aux 头持续预测被记住的身份）应帮助**压缩派**架构（GRU/evidence）克服隐式压缩瓶颈。

## 二、任务与设计

- 任务：单身份延迟回忆（合成）——[身份 one-hot(帧0), (delay-1) 空帧]，末帧决策输出身份。swap 探针（翻转身份→选择映射）。
- 对照：gru_base / gru_aux / evidence_base / evidence_aux（aux = 帧 1..T-1 每帧预测身份 one-hot；α=0.5 主，扫描 0.1-1.0；同预算同循环）。
- 语料：synthetic_single（`train_aux_memory_content.py`），heldout 256，300 updates。

## 三、结果（3 seed 全确认）

| 延迟 | gru_base | **gru_aux** | evidence_base | **evidence_aux** |
|---|---|---|---|---|
| d=8/16 | 1.000 | 1.000 | 1.000 | 1.000 |
| **d=32** | **0.508（随机）** | **1.000** | 1.000 | 1.000 |
| **d=64** | **0.508（随机）** | **1.000** | **0.508（随机）** | **1.000** |

- 3/3 seed（93_337/222/333）完全一致；
- α 扫描 0.1/0.2/1.0：全部 1.000（效果对 α 稳健，0.1 即够）；
- swap evidence：gru_aux d=32 = 1.0（真记忆，非捷径）；
- 无泄漏：aux 预测帧 1..T-1 全为空帧（身份仅帧 0 出现）。

**机制**：aux 在每帧施加"身份保持"监督 → 压缩派隐状态被训练成**持续携带记忆内容** → 决策帧可直接读出。相当于给"隐式压缩"加显式内容锚点——正是 JEPA"预测记忆内容驱动记忆"的本意。

## 四、RL 扩展：记忆内容预测在 RL 下帮助 GRU（修正"RL aux 负担"）

DecideAfterDelay RL（`train_decide_after_delay_rl.py --aux-memory --gru-focus`，100 updates，64 eval）：

| 延迟 | gru orig/swap | **gru_aux orig/swap** | aux evidence |
|---|---|---|---|
| d=8（3 seed）| 0.54 / 0.46（均值）| **0.781 / 0.219** | **+0.562** |
| d=32（3 seed）| 0.562 / 0.438 | **0.797 / 0.203** | **+0.594** |

- **修正既有结论**：此前"aux 在 RL 中是负担（evidence_pred 掉 0.10）"针对的是 **surprise 重建目标（输入空间重建）**；**语义记忆内容预测（身份 one-hot）在 RL 下是帮助**——GRU evidence 从 ≈0 到 +0.56（3/3 seed 一致），且 gru_aux 比 base 更稳定（0.781 恒定 vs 0.44-0.70）。
- 两类 aux 性质不同：重建不可用信息 = 噪声；预测语义记忆内容 = 密集记忆保持监督。

## 五、与既有结论的整合

| 场景 | aux 类型 | 效果 | 结论 |
|---|---|---|---|
| MemoryS7 RL（sparse reward）| SPR latent | 无增量 | 评估攻破，不可诊断 |
| DecideAfterDelay RL | surprise 重建 | **负担（-0.10）** | 重建式 aux 进策略梯度有害 |
| **DecideAfterDelay RL** | **记忆内容预测** | **帮助（evidence 0→+0.56）** | **语义 aux 在 RL 有效** |
| 真实 v2 监督（d=8）| 记忆内容预测 | 无增量 | 主任务饱和 |
| **单身份合成监督（d≥32）** | 记忆内容预测 | **决定性（0.508→1.0）** | **记忆保持压力场景有效** |

**架构含义**：surprise/预测类辅助目标必须区分类型——**重建式（输入空间）**是噪声/负担，**语义式（记忆内容标签）**是记忆保持的密集监督，监督与 RL 下均有效。JEPLM 的"记忆内容预测"定位**成立且普适**（监督/RL 双域）。

## 六、连续流扩展：aux 只能教一个时标（压缩派结构性盲区）

DecideStream RL 连续流（u=3 g=4，`train_decide_stream_rl.py --aux-memory --gru-focus`，3 seed）：

| 模型 | query 均值 | cross 均值 |
|---|---|---|
| gru（base）| 0.521 | 0.478 |
| gru_aux（预测当前）| **0.807** | 0.448 |
| gru_aux（预测上一）| 0.493 | 0.522 |
| **gru_aux2（双头：当前+上一）** | 0.804 | 0.488 |
| evidence（无 aux，参考）| 0.932 | **0.806** |

**结论**：连续流下 aux 目标选择**偏置记忆内容**——教当前则 query 涨 cross 崩；教上一则 query 崩 cross 微升；**双头同时监督也不行**（表现≈只教当前）。GRU 单隐状态无法同时维持多时标内容，密集 aux 监督（单头/双头）都无法克服——**跨段保持是压缩架构的结构性限制**，与训练信号无关。显式槽位（evidence）无任何辅助即 query/cross 双高，机制级强化"显式槽位 > 隐式压缩"。

## 七、极限与 PLWM 对照：aux 是长延迟记忆的通用解药（d=128）

| 延迟 | gru_base | gru_aux | evidence_base | evidence_aux | **plwm（无 aux）** |
|---|---|---|---|---|---|
| d=32 | 0.508 | **1.000** | 1.000 | 1.000 | 1.000 |
| d=64 | 0.508 | **1.000** | 0.508 | **1.000** | **0.508** |
| d=128 | 0.508 | **1.000** | 0.508 | **1.000** | **0.508** |

- **PLWM（8 显式槽位）在 d=64/128 也崩（0.508）**——显式槽位并非无限：超长延迟下身份帧被槽位竞争/干扰挤出（此前 d≤32 无此问题）。这修正"槽位派在长延迟必胜"的直觉——**所有架构在足够长延迟下都有极限**。
- **容量探针（机制确认）**：d=64 需 ≥16 槽、d=128 需 ≥32 槽（8 槽崩、16 槽 d=64 恢复、32 槽 d=128 恢复）——**槽位数须覆盖任务时间跨度（约延迟的 1/4~1/2）**，这是显式槽位设计的量化约束。
- **aux 是所有架构的通用长延迟解药**：gru/evidence +aux 在 d=128 仍 1.0（语义内容预测是"保持记忆"的密集监督，不限架构）。
- 定位修正：显式槽位 > 隐式压缩（中短延迟与流式多时标）；超长延迟下**语义 aux 是更普适的补丁**，槽位与压缩都受益；槽位派须按时间跨度配槽数。

## 八、遗留（诚实记录）

- **RMT + aux 未测**：流式 RMT 的跨段压缩"不可学"结论是否因 aux 而松动？——流式 RMT 是 RL 策略，aux 进 RL 落入"负担"区（已有诊断），需 RL+aux 混合设计，工程量大，列后续。
- 双身份/干扰场景下 aux 的帮助未测（单身份已验证核心机制）。
- d 边界：GRU 崩点（d≥32 单身份）处 aux 生效；d≤16 无增量空间。
